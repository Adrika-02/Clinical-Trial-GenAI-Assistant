# Interview Prep: SHAP Explainability

**1. How does SHAP actually work for a Logistic Regression model, in your own words?**
For a linear model, each class's score is exactly `coef · x + intercept` — a weighted sum of feature values. SHAP's `LinearExplainer` computes each feature's contribution to that sum, referenced against a background distribution (I use up to 200 real training notes as the baseline), so the "SHAP value" for a word is essentially "how much did this word's TF-IDF weight push the score above/below the average note." Because the underlying model is genuinely linear, this isn't an approximation the way SHAP is for a tree ensemble or neural net — it's an exact decomposition of the real decision function.

**2. Why build a separate explainer per class instead of one explainer for the whole multiclass model?**
Multinomial Logistic Regression has one coefficient vector per class (`coef_` has shape `(n_classes, n_features)`), and each class's raw score is independent before the softmax normalization. I extract the specific coefficient row for the class I want to explain (e.g. "Severe AE") and build a `shap.LinearExplainer((coef_row, intercept), background)` directly from it (`src/explainability/shap_explain.py`). This gives a clean, class-specific answer to "what pushed this note toward Severe AE" rather than a blended explanation across all three classes.

**3. Walk me through one real global SHAP result and what it tells you clinically.**
For the Severe AE class, the top global features by mean |SHAP value| are `review`, `pending`, `suspend`, `urgent`, `evaluation`, `chest`, `severe` — these are literally the vocabulary an investigator uses when escalating and stopping a dose ("study drug held pending safety assessment," "urgent clinical review"). That's a good sanity check: the model isn't keying off something spurious like patient ID artifacts or note length, it's keying off the exact clinical action-language a domain expert would expect.

**4. Give an example of a local (single-note) explanation and how you'd present it to a non-technical stakeholder.**
For the note *"Feeling unsteady on their feet serious enough to warrant an urgent evaluation this visit. Study drug held pending safety assessment,"* the model predicts Severe AE, and the top three SHAP-positive words are 'urgent', 'pending', and 'evaluation'. I auto-generate a one-sentence narrative from this ("The words 'urgent', 'pending' and 'evaluation' were the strongest predictors of Severe AE classification in this note") rather than showing a raw SHAP plot — a clinical reviewer doesn't need to read a waterfall chart to trust the flag, they need one sentence that matches their own clinical intuition about the note.

**5. What's a limitation of SHAP here that you'd flag proactively?**
SHAP explains the model's decision, not ground truth — if the classifier has learned a spurious correlation (e.g. a word that happens to co-occur with severe cases in this dataset but isn't clinically causal), SHAP will faithfully report that spurious correlation as important. It's a tool for auditing and debugging the model's actual behavior, not a substitute for clinical validation of whether the model's behavior is itself correct. I'd also note that because I use TF-IDF, only words that survive vectorization (min_df=2, top 2,000 features) can ever appear in an explanation — a rare-but-important word could be invisible to both the model and its explanation.
