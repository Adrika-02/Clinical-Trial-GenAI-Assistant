# Interview Prep: NLP Adverse-Event Classifier

**1. Why Logistic Regression instead of Random Forest or a transformer model for the AE classifier?**
Three reasons, in order of importance for this use case: (1) interpretability — Logistic Regression's coefficients map directly onto SHAP's exact linear explainer, so every global/local explanation is an exact computation, not an approximation, which matters a great deal in a regulated pharma context where "why did the model flag this" needs a defensible answer; (2) the bag-of-lemmas TF-IDF feature space (2,000 features, 1-2 grams) is close to linearly separable for this task, so a linear model captures nearly all the available signal — my F1-macro of 0.851 with Logistic Regression is unlikely to improve meaningfully with a higher-capacity model on a dataset this size (2,400 training notes); (3) training/inference cost — this needs to run inline in a Streamlit request in under a second, which rules out a transformer without a GPU.

**2. Your precision (78.7% macro) is noticeably lower than recall (94.9% macro) — is that a problem?**
No — it's a deliberate design choice via `class_weight="balanced"` in the Logistic Regression, and it's the right tradeoff for pharmacovigilance specifically. A false negative (missing a real adverse event) is far more costly than a false positive (flagging a benign note for review, which a clinician can dismiss in seconds). The lower precision mostly comes from the smallest class — only 47 Severe AE examples in the full dataset — where the model errs toward over-flagging rather than under-flagging.

**3. Explain your TF-IDF + Logistic Regression pipeline end-to-end, including preprocessing.**
Raw note text goes through SpaCy: tokenization, lemmatization, and stopword removal — except I explicitly keep negation words ("no", "not", "none", "never") in the stopword-removal step, because "no nausea" and "nausea" need to look different to a bag-of-words model. The cleaned lemma string is vectorized with `TfidfVectorizer(max_features=2000, ngram_range=(1,2), min_df=2)`, then classified with `LogisticRegression(class_weight="balanced")` inside a single sklearn `Pipeline`, trained on an 80/20 stratified split (2,400 train / 600 test notes).

**4. How would you improve this classifier if you had more time or a bigger budget?**
I'd try three things in order of expected payoff: (1) more training data specifically for the Severe AE class (only 47 examples trial-wide is thin for a model to learn robust boundaries — active learning or targeted oversampling would help); (2) a domain-pretrained clinical embedding model (e.g. a BioClinicalBERT-style encoder) as a drop-in replacement for TF-IDF, which would likely raise the ceiling especially on the ambiguous/paraphrased notes, at the cost of losing the exact-linear SHAP mapping; (3) calibrating the confidence scores (Platt scaling) since raw Logistic Regression probabilities aren't automatically well-calibrated, which matters if the confidence score is shown to a clinician as a decision input.

**5. How do you know the 92.2% accuracy isn't inflated by an easy dataset?**
I specifically engineered against that failure mode — see the data-generation interview prep for the story of catching an initial 100%-accuracy result and diagnosing it as a template-shortcut artifact. After adding text/label ambiguity (notes written at a different severity than their adjudicated label 15% of the time) and lexical variety (symptom synonyms, distractor sentences in "No AE" notes), accuracy dropped to a realistic 92.2% with the confusion concentrated in exactly the ambiguous cases — that's the signature of a model learning genuine signal rather than memorizing surface patterns.
