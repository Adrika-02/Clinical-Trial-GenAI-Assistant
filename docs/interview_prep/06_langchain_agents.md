# Interview Prep: GenAI Agents (LangChain + Bedrock)

**1. Walk me through what happens end-to-end when a user asks "What is the average HbA1c reduction in the treatment arm?"**
The router (`src/agents/router.py`) makes one fast, tool-free LLM call to classify the question into `data_analysis` / `clinical_notes` / `insight`, then dispatches to the matching agent. For this question, the Data Analysis Agent (built with LangChain 1.x's `create_agent`, a LangGraph-based tool-calling loop) is invoked with two tools: `get_database_schema` and `run_sql_query`. In a real run, the model actually hallucinated a table name on its first attempt (`clinical_trial_data`), got a genuine SQL error back from the tool, and self-corrected to the real schema on the next turn before producing the correct answer — that's real multi-step agentic recovery, not scripted.

**2. Why did you build three separate agents instead of one agent with all the tools?**
Separation of concerns and prompt clarity. Each agent has a narrow, well-specified job (SQL analysis, note retrieval + summarization, or cross-source executive synthesis) with a system prompt tuned to that job — the Data Analysis Agent's prompt is entirely about writing correct SQL and never fabricating numbers, while the Insight Agent's prompt is about business framing and pulling from four different tools. A single mega-agent with all seven tools would have a harder time reliably picking the right tool for ambiguous questions, and the router's job (classify → dispatch) is much easier to get right than "hope the model always picks the right tool out of everything."

**3. Your project is scoped around AWS Bedrock — why is the live demo running on Groq instead?**
Bedrock's Claude models require an AWS Marketplace subscription, which itself requires a valid payment method on the AWS account — a billing gate, not a technical limitation. I built and verified the Bedrock IAM/region/model wiring directly (I have a working IAM user, confirmed the correct cross-region inference profile ID, and got a live successful `converse()` call before the Marketplace payment wall appeared), so the integration code is real and tested, not speculative. Every agent calls a single `get_llm()` factory (`src/agents/bedrock_llm.py`) that never leaks provider-specific code into the agents themselves, so swapping `LLM_PROVIDER=bedrock` back in later is a one-line env change — this is a deliberate architecture decision, not a workaround bolted on after the fact.

**4. Tell me about a real bug you hit building these agents, and how you found it.**
The Clinical Notes Agent's `search_clinical_notes` tool declared `visit_week: int` and `limit: int` parameters, but Groq's function-calling API sometimes emits numeric tool-call arguments as JSON strings (e.g. `"visit_week": "-1"`), and Groq validates the emitted JSON strictly against the declared schema — so a string value against a declared `integer` type caused a hard 400 error that broke both the Clinical Notes Agent and the PDF report's insight-generation step (which reuses the same agent). I fixed it by declaring those parameters as `str` and parsing to `int` inside the function body, which sidesteps provider-side type validation while keeping the tool's actual behavior identical. I found it by testing the agent directly and reading the literal error message rather than assuming a router/prompt problem.

**5. How do you keep the agents from hallucinating numbers in their final answer?**
Two mechanisms. First, every system prompt explicitly instructs the agent to only cite numbers that came from an actual tool result and never fabricate a statistic — this is prompt-level, not a hard guarantee. Second, and more importantly, for the Data Analysis Agent I don't trust the model's prose numbers at all for anything downstream — I extract the literal SQL query it executed from the tool-call history and re-run it myself (`_extract_last_sql` + `fetch_dataframe`) to build the chart and any programmatic consumption, so the visualization is guaranteed to reflect a real, re-executable query rather than the model's restated text.
